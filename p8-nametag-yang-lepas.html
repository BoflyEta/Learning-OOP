Nametag yang Lepas

Properti static itu punya class-nya, bukan punya instance. Terus this juga bisa "lupa" objek aslinya kalau method-nya dicopot dari tempatnya.

Durasi: 120 menit Prasyarat: class & method (Modul 1–2) Bahasa: JavaScript (ES6+)
1

Papan Pengumuman Pabrik: static

Biasanya tiap instance punya datanya masing-masing — this.nama itu cuma milik satu objek doang. Tapi kadang kita butuh data yang dibagi bareng-bareng oleh SEMUA instance, punya class itu sendiri, bukan punya salah satu produknya. Coba bayangin papan pengumuman di pabrik yang nampilin "Total diproduksi hari ini" — itu bukan stiker yang nempel di satu produk doang, kan?

static-counter.js
class Counter {
  static totalDibuat = 0; // milik CLASS, bukan instance

  constructor(nama) {
    this.nama = nama;
    Counter.totalDibuat++; // update papan pengumuman pabrik
  }

  static laporanTotal() {
    console.log(`Total Counter yang pernah dibuat: ${Counter.totalDibuat}`);
  }
}

const c1 = new Counter("A");
const c2 = new Counter("B");
const c3 = new Counter("C");

console.log(c1.nama, c2.nama, c3.nama);
Counter.laporanTotal(); // dipanggil dari CLASS, bukan dari instance
Klik "Jalankan" untuk melihat hasilnya.
Perhatiin nih: Counter.laporanTotal() dipanggil lewat nama class-nya, bukan lewat c1, c2, atau c3. Emang gitu, static member itu nggak "punya" instance mana pun.
2

Nametag yang Terlepas

Method itu biasanya "tahu" objek mana yang manggil dia lewat this — mirip karyawan yang pakai nametag pas kerja di kantornya. Tapi begitu method itu dicopot dari objeknya terus dipanggil sendirian, nametag-nya ikut copot juga — this jadi bingung, nggak tahu lagi harus nunjuk ke siapa.

this-hilang.js
class Tombol {
  constructor(label) {
    this.label = label;
  }
  klik() {
    console.log(`${this.label} diklik!`);
  }
}

const tombolSimpan = new Tombol("Simpan");
tombolSimpan.klik(); // aman, this = tombolSimpan (nametag masih menempel)

const fungsiKlikSaja = tombolSimpan.klik; // nametag ikut lepas di sini!
try {
  fungsiKlikSaja(); // this sudah tidak jelas lagi
} catch (e) {
  console.log("Error:", e.message);
}
Klik "Jalankan" untuk melihat masalahnya.
Ini bukan bug JavaScript, ya — ini emang cara kerja this, yang ditentukan dari CARA method itu dipanggil, bukan dari MANA dia ditulis. Bug klasik kayak gini sering banget muncul waktu method dipasang jadi event handler atau callback.
3

Menempelkan Nametag Secara Permanen

Nah, ada dua cara buat ngunci this biar nggak ikutan lepas: pakai arrow function (this-nya kekunci sejak dibuat), atau pakai .bind() (this-nya dipaksa nempel ke objek tertentu).

menempelkan-this.js
class Tombol {
  constructor(label) {
    this.label = label;
    this.klikArrow = () => { // arrow function "menstaples" this secara permanen
      console.log(`${this.label} diklik (arrow)!`);
    };
  }
  klik() {
    console.log(`${this.label} diklik (biasa)!`);
  }
}

const tombolSimpan = new Tombol("Simpan");

const fungsiArrow = tombolSimpan.klikArrow;
fungsiArrow(); // tetap aman, this sudah terkunci sejak awal

const fungsiBind = tombolSimpan.klik.bind(tombolSimpan);
fungsiBind(); // aman juga, karena this dipaksa terikat lewat bind()
Klik "Jalankan" untuk melihat hasilnya.

Latihan: Perbaiki Bug "this hilang"

Coba jalanin dulu kode di bawah ini — bakal muncul error karena penghitung.tambah kecopot dari objeknya waktu dipakai sebagai callback forEach. Tugas kamu: perbaiki baris yang ditandai biar this tetap nunjuk ke penghitung.

latihan-perbaiki-bug.js — bisa diedit
Klik "Jalankan" untuk melihat error-nya dulu, lalu perbaiki.
kunci-jawaban.js
const penghitung = new Penghitung("Kasir 1");
const daftarTransaksi = [10000, 20000, 5000];

// perbaikan #1: bungkus dengan arrow function
daftarTransaksi.forEach(jumlah => penghitung.tambah(jumlah));

// perbaikan #2 (alternatif): pakai .bind()
// daftarTransaksi.forEach(penghitung.tambah.bind(penghitung));
5

Cek Pemahaman

1. Sebenernya apa bedanya properti/method static sama yang biasa (instance)?

Ibarat papan pengumuman pabrik: cuma ada satu papan, tapi dibaca dan diupdate sama semua lini produksi.

2. Kenapa sih this bisa jadi undefined kalau method-nya dicopot dari objeknya terus dipanggil sebagai fungsi biasa?

Ini konsep penting banget: this itu sifatnya dinamis, ditentukan pas dipanggil, bukan pas ditulis.

3. Kenapa arrow function di dalam class (kayak this.klikArrow = () => {...}) nggak kehilangan this walaupun dicopot dari objeknya?

Arrow function itu nggak punya this sendiri — dia "minjem" this dari lingkungan tempat dia ditulis, selamanya.

4. Sebenernya .bind(objek) itu ngapain sih ke sebuah method?

bind() itu cara lain buat "nempelin nametag" — hasilnya fungsi baru yang this-nya udah tetap, nggak bisa lepas lagi.

6

Ringkasan Pertemuan 8

  • static member itu punya class-nya, dibagi ke semua instance — ibarat papan pengumuman pabrik, bukan label yang nempel di tiap produk.
  • this itu ditentukan dari cara method dipanggil, bukan dari tempat dia ditulis — bisa "ilang" kalau method-nya dicopot dari objeknya.
  • Arrow function di dalam class ngunci this sejak awal dibuat, jadi aman dipakai sebagai callback.
  • .bind(objek) maksa this nempel ke objek tertentu — cara lain buat ngatasin masalah yang sama.
