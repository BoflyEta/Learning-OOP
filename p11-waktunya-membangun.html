Waktunya Membangun

Dari denah yang udah dirancang di Pertemuan 10, sekarang saatnya benar-benar ngoding — dibangun bertahap per checkpoint, sekalian belajar debug error yang paling sering ketemu.

Durasi: 120 menit Prasyarat: Pertemuan 10 (Perencanaan & Desain Proyek) Bahasa: JavaScript (ES6+)
1

Bangun Bertahap, Bukan Sekaligus

Coba bayangin tukang bangun yang kerja proyek rumah. Dia nggak masang tembok, atap, instalasi listrik, sama cat sekaligus dalam satu hari tanpa pernah ngecek apa-apa. Yang dia lakuin gini: gali dan cor pondasi dulu, terus CEK — udah kuat apa belum, udah rata apa belum. Baru kalau oke, lanjut masang tembok, terus CEK lagi. Baru kalau tembok udah beres dan lurus, lanjut atap.

Tiap tahap dicek dulu sebelum lanjut ke tahap berikutnya — istilahnya checkpoint. Kalau ada yang salah di pondasi, ketauannya dari awal, pas masalahnya masih kecil dan gampang dibenerin. Bandingin kalau dia baru ngecek semuanya di akhir, pas rumah udah jadi — kalau ternyata pondasinya miring, bongkar ulang semuanya jadi lebih mahal dan ribet.

Ngoding proyek persis sama. Nulis sedikit kode, jalanin, pastiin hasilnya bener, baru nambah dikit lagi. Jangan nulis 200 baris kode dulu terus baru dicoba sekali di akhir — kalau ternyata error, kamu bakal bingung banget nyari di baris mana masalahnya muncul, soalnya ada 200 baris yang harus dicurigai.

Gampangnya gini: tiap kali kamu selesai nulis satu bagian kecil dari proyek — satu method, satu fitur — langsung console.log() dan jalanin. Kalau bener, lanjut. Kalau salah, kamu tau persis kode yang barusan kamu tulis itu yang jadi biang keroknya, bukan nyari jarum di tumpukan jerami 200 baris.

Checkpoint 1: Lengkapi DaftarTugas

Inget Tugas dan DaftarTugas yang kita desain dan mulai bangun di Pertemuan 10? Sekarang kita lanjutin — checkpoint pertama proyek ini. Struktur dasarnya persis sama kayak sebelumnya, cuma kita nambah dua method baru di DaftarTugas: hapusSelesai() buat ngebersihin tugas yang statusnya udah "selesai" dari daftar, dan tampilkanSemua() buat nampilin semua tugas apa pun statusnya (beda sama tampilkanBelumSelesai() yang udah ada).

checkpoint-1.js
class Tugas {
  #status = "belum selesai";
  constructor(judul, tenggat) {
    this.judul = judul;
    this.tenggat = tenggat;
  }
  tandaiSelesai() {
    this.#status = "selesai";
  }
  get status() { return this.#status; }
}

class DaftarTugas {
  #daftar = [];
  tambah(tugas) { this.#daftar.push(tugas); }
  hapusSelesai() {
    this.#daftar = this.#daftar.filter(t => t.status !== "selesai");
  }
  tampilkanSemua() {
    this.#daftar.forEach(t => console.log(`- ${t.judul} (${t.tenggat}) [${t.status}]`));
  }
}

const dt = new DaftarTugas();
const t1 = new Tugas("Belajar OOP", "30 Agustus");
const t2 = new Tugas("Kerjain PR", "1 September");
t1.tandaiSelesai();
dt.tambah(t1);
dt.tambah(t2);
console.log("sebelum dibersihkan:");
dt.tampilkanSemua();
dt.hapusSelesai();
console.log("sesudah dibersihkan:");
dt.tampilkanSemua();
Klik "Jalankan" untuk melihat hasilnya.
Checkpoint lolos kalau: setelah hapusSelesai() dipanggil, cuma tugas yang belum selesai yang tersisa di daftar — "Belajar OOP" (yang udah ditandain selesai) hilang, "Kerjain PR" tetap ada. Ini persis cara kerja checkpoint: satu fitur kecil, dites, baru lanjut ke checkpoint berikutnya.
3

Checkpoint 2: Nambah Fitur Pakai Inheritance & Polymorphism

Checkpoint dasar udah lolos, sekarang kita perluas. Bayangin ada kebutuhan baru: sebagian tugas itu lebih "penting" daripada yang lain, dan pas ditandai selesai, dia harus kasih pesan spesial. Daripada bikin class baru dari nol, kita pakai inheritance — TugasPenting extends Tugas — biar semua properti dan method Tugas otomatis kewarisin, dan kita tinggal nambah yang beda aja: properti prioritas, plus override method tandaiSelesai().

Perhatiin di override-nya, kita tetap manggil super.tandaiSelesai() dulu — biar logika asli dari Tugas (ubah status jadi "selesai") tetap jalan — baru nambahin perilaku ekstra di atasnya. Ini konsep yang udah kita bahas di Pertemuan 4-6: inheritance buat mewarisi, override buat mengubah perilaku spesifik, dan polymorphism muncul waktu kita loop bareng array campuran Tugas dan TugasPenting — method yang dipanggil sama persis (tandaiSelesai()), tapi hasilnya beda tergantung objeknya.

checkpoint-2.js
class Tugas {
  #status = "belum selesai";
  constructor(judul, tenggat) {
    this.judul = judul;
    this.tenggat = tenggat;
  }
  tandaiSelesai() {
    this.#status = "selesai";
    console.log(`✓ ${this.judul} selesai`);
  }
  get status() { return this.#status; }
}

class TugasPenting extends Tugas {
  constructor(judul, tenggat, prioritas) {
    super(judul, tenggat);
    this.prioritas = prioritas;
  }
  tandaiSelesai() {
    super.tandaiSelesai();
    console.log(`🎉 tugas penting (prioritas ${this.prioritas}) selesai!`);
  }
}

const semuaTugas = [
  new Tugas("Belajar OOP", "30 Agustus"),
  new TugasPenting("Deploy ke production", "31 Agustus", "tinggi")
];
semuaTugas.forEach(t => t.tandaiSelesai());
Klik "Jalankan" untuk melihat hasilnya.
Perhatiin baris terakhir: semuaTugas.forEach(t => t.tandaiSelesai()) manggil method yang sama persis buat tiap elemen, tapi Tugas biasa cuma nyetak satu baris ✓, sementara TugasPenting nyetak dua baris — baris ✓ dari super.tandaiSelesai(), terus baris 🎉 tambahan. Objek yang beda, perilaku beda, meski dipanggil dengan cara yang sama — itulah polymorphism kepake di proyek nyata.
4

Kalau Ada yang Error, Ini Cara Debug-nya

Waktu ngoding proyek beneran, error itu wajar banget — bahkan programmer berpengalaman ketemu error tiap hari. Yang beda cuma seberapa cepat mereka ngenalin pesan errornya dan tau ke mana harus ngebenerin. Dua bug di bawah ini adalah yang paling sering bikin pemula muter-muter bingung.

Class itu wajib dipanggil pakai new. Coba jalankan kode ini — sengaja lupa new-nya.

bug-lupa-new.js
class Tugas2 { constructor(judul) { this.judul = judul; } }
const t = Tugas2("Belajar");
Klik "Jalankan" untuk melihat errornya.
Baca pesan errornya: Class constructor Tugas2 cannot be invoked without 'new'. JavaScript langsung ngasih tau persis apa masalahnya — class harus dipanggil pakai new, nggak bisa dipanggil kayak fungsi biasa.

Tinggal tambahin new di depan pemanggilan constructor-nya.

bug-lupa-new-fix.js
class Tugas2 { constructor(judul) { this.judul = judul; } }
const t = new Tugas2("Belajar");
console.log(t.judul);
Klik "Jalankan" untuk melihat hasilnya.

Inget "Nametag yang Lepas" di Pertemuan 8? Ini kejadian persis itu: method diambil sebagai callback polos, jadi kehilangan koneksinya ke this.

bug-this-ilang.js
class DaftarTugas3 {
  #daftar = [];
  tambah(t) { this.#daftar.push(t); console.log("ditambahkan:", t); }
}
const d = new DaftarTugas3();
["A", "B"].forEach(d.tambah);
Klik "Jalankan" untuk melihat errornya.
Baca pesan errornya: Cannot read properties of undefined (reading '#daftar'). Waktu d.tambah dikasih ke forEach tanpa tanda kurung, method itu "lepas" dari objek d — nametag-nya (this) ketinggalan. Pas dipanggil, this jadi undefined, dan this.#daftar nggak nemu apa-apa.

Bungkus pakai arrow function biar this tetap nempel ke d waktu dipanggil.

bug-this-ilang-fix.js
class DaftarTugas3 {
  #daftar = [];
  tambah(t) { this.#daftar.push(t); console.log("ditambahkan:", t); }
}
const d = new DaftarTugas3();
["A", "B"].forEach(x => d.tambah(x));
Klik "Jalankan" untuk melihat hasilnya.

Latihan: Lengkapi urutkanByTenggat()

Checkpoint terakhir buat sesi ini: lengkapi method urutkanByTenggat() di DaftarTugas4 di bawah, supaya daftar tugas terurut dari tenggat yang paling dekat. Kamu bakal butuh .sort() dan new Date(...) buat ngebandingin dua tanggal.

latihan-urutkan.js — bisa diedit
Lengkapi kode lalu klik "Jalankan".
kunci-jawaban.js
class Tugas { constructor(judul, tenggat) { this.judul = judul; this.tenggat = tenggat; } }

class DaftarTugas4 {
  #daftar = [];
  tambah(t) { this.#daftar.push(t); }
  urutkanByTenggat() {
    this.#daftar.sort((a, b) => new Date(a.tenggat) - new Date(b.tenggat));
  }
  tampilkanSemua() {
    this.#daftar.forEach(t => console.log(`- ${t.judul} (${t.tenggat})`));
  }
}

const dt2 = new DaftarTugas4();
dt2.tambah(new Tugas("Tugas C", "2026-09-05"));
dt2.tambah(new Tugas("Tugas A", "2026-09-01"));
dt2.tambah(new Tugas("Tugas B", "2026-09-03"));
dt2.urutkanByTenggat();
dt2.tampilkanSemua();
Kenapa class Tugas ditulis ulang di sini? Soalnya tiap kode di halaman ini dijalankan di "kotak pasir" (sandbox) masing-masing yang terpisah — nggak saling nyambung walau tampilannya berurutan di halaman yang sama. Jadi tiap latihan yang butuh Tugas harus bawa definisinya sendiri biar bisa jalan mandiri.

Cek Pemahaman

1. Kenapa "bangun bertahap per checkpoint" lebih aman daripada nulis banyak kode sekaligus baru dites di akhir?

Sama kayak tukang bangun yang ngecek pondasi dulu sebelum lanjut tembok — masalah ketauan dari awal, pas masih kecil dan gampang dibenerin.

2. Apa yang terjadi kalau kita lupa pakai new waktu bikin instance dari sebuah class, misalnya Tugas2("Belajar")?

Class memang wajib dipanggil pakai new — kalau nggak, JavaScript langsung menolak dan kasih pesan error yang jelas soal itu.

3. Kenapa this bisa "ilang" waktu kita nulis ["A", "B"].forEach(d.tambah), dan gimana cara benerinnya?

Persis konsep "Nametag yang Lepas" di Pertemuan 8 — method yang diambil sebagai referensi polos kehilangan koneksinya ke this; arrow function menjaga koneksi itu tetap ada.

4. Waktu array campuran Tugas dan TugasPenting di-loop dan masing-masing dipanggil tandaiSelesai(), kenapa hasilnya bisa beda-beda?

Ini polymorphism kepake langsung di proyek nyata: satu pemanggilan method yang sama, hasilnya beda tergantung objek aslinya.

5. Di dalam TugasPenting.tandaiSelesai(), apa fungsi baris super.tandaiSelesai()?

super.tandaiSelesai() memastikan logika asli (ubah status, cetak pesan) tetap jalan, jadi override tidak menggantikan tapi menambah perilaku di atasnya.

6. Ada kode begini: class Kucing{constructor(n){this.nama=n;}bunyi(){console.log(this.nama);}} const daftarNama=["Milo","Kiki"]; daftarNama.forEach(new Kucing("x").bunyi); — method bunyi dikasih langsung ke forEach tanpa tanda kurung dan meledak error this undefined. Apa penyebabnya?

Pola bugnya identik dengan Bug 2 di sheet ini: begitu method diambil tanpa tanda kurung dan diteruskan sebagai callback polos, this-nya lepas. Solusinya sama — bungkus pakai arrow function.

Ringkasan Pertemuan 11

  • Bangun bertahap + cek tiap checkpoint jauh lebih aman daripada nulis banyak kode sekaligus baru dites sekali di akhir — error jadi gampang dilacak sumbernya.
  • Error "cannot be invoked without 'new'" artinya lupa pakai new waktu bikin instance dari sebuah class.
  • Error "Cannot read properties of undefined (reading '#daftar')" biasanya berarti this "ilang" karena method diambil sebagai callback polos — benerinnya dengan membungkus pakai arrow function.
  • Inheritance, override, dan polymorphism yang udah dipelajari di modul-modul sebelumnya langsung kepake nyata di proyek: TugasPenting extends Tugas nambah perilaku baru tanpa nulis ulang semuanya dari nol.
