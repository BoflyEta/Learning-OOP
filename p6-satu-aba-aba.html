Satu Aba-Aba

Coba bayangin aba-aba "mulai!" di balapan — mobil melaju, motor menyalip, sepeda mengayuh. Satu perintah doang, tapi cara responsnya beda-beda.

Durasi: 120 menit Prasyarat: method overriding (Pertemuan 5) Bahasa: JavaScript (ES6+)
1

Satu Perintah, Banyak Respons

Masih inget Lingkaran dan PersegiPanjang dari Pertemuan 5? Keduanya sama-sama punya method luas(), meski rumusnya beda total. Nah sekarang coba lihat apa yang terjadi kalau keduanya dikumpulin dalam satu daftar, terus dipanggil .luas() secara seragam — tanpa kode pemanggilnya tahu bentuk spesifik yang mana.

satu-perintah.js
class Bentuk {
  constructor(nama) { this.nama = nama; }
  luas() { return 0; }
}
class Lingkaran extends Bentuk {
  constructor(jariJari) { super("Lingkaran"); this.jariJari = jariJari; }
  luas() { return Math.PI * this.jariJari ** 2; }
}
class PersegiPanjang extends Bentuk {
  constructor(panjang, lebar) { super("Persegi Panjang"); this.panjang = panjang; this.lebar = lebar; }
  luas() { return this.panjang * this.lebar; }
}
class Segitiga extends Bentuk {
  constructor(alas, tinggi) { super("Segitiga"); this.alas = alas; this.tinggi = tinggi; }
  luas() { return 0.5 * this.alas * this.tinggi; }
}

const daftarBentuk = [
  new Lingkaran(7),
  new PersegiPanjang(5, 3),
  new Segitiga(6, 4)
];

// satu perintah yang sama, .luas(), dipanggil ke semua bentuk berbeda
daftarBentuk.forEach(b => {
  console.log(`${b.nama}: luas = ${b.luas().toFixed(2)}`);
});
Klik "Jalankan" untuk melihat hasilnya.
Nah, inilah polymorphism: kode b.luas() ditulis sekali doang, tapi hasilnya beda-beda tergantung objek mana yang lagi dipanggil — masing-masing merespons dengan caranya sendiri.
2

Aba-Aba Balapan

Coba bayangin aba-aba "MULAI!" di garis start balapan. Semua peserta dengar perintah yang sama persis, tapi Mobil melaju di jalan raya, Motor menyalip di celah sempit, Sepeda mulai mengayuh pelan-pelan. Satu aba-aba, gerakannya macam-macam — itulah polymorphism dalam bentuk yang paling literal.

aba-aba-balapan.js
class Kendaraan {
  constructor(nama) { this.nama = nama; }
  mulai() {
    console.log(`${this.nama} bersiap...`);
  }
}
class Mobil extends Kendaraan {
  mulai() {
    console.log(`${this.nama} melaju kencang di jalan raya!`);
  }
}
class Motor extends Kendaraan {
  mulai() {
    console.log(`${this.nama} menyalip lincah di celah kemacetan!`);
  }
}
class Sepeda extends Kendaraan {
  mulai() {
    console.log(`${this.nama} mulai mengayuh pelan-pelan.`);
  }
}

const pesertaBalapan = [
  new Mobil("Mobil Nomor 1"),
  new Motor("Motor Nomor 2"),
  new Sepeda("Sepeda Nomor 3")
];

console.log("=== ABA-ABA: MULAI! ===");
pesertaBalapan.forEach(k => k.mulai());
Klik "Jalankan" untuk melihat hasilnya.
3

Bonus: Duck Typing

Di JavaScript, polymorphism bahkan nggak selalu butuh hubungan extends lho. Kalau dua objek sama-sama punya method dengan nama yang sama, keduanya bisa dipanggil secara seragam — biarpun class-nya sama sekali nggak berhubungan.

duck-typing.js
class Robot {
  bicara() {
    console.log("BEEP BOOP, saya robot.");
  }
}
class Manusia {
  bicara() {
    console.log("Halo, saya manusia.");
  }
}

const pembicara = [new Robot(), new Manusia()];
pembicara.forEach(p => p.bicara());
// Robot dan Manusia TIDAK punya hubungan inheritance apa pun,
// tapi keduanya punya method bicara() -> tetap bisa dipanggil seragam.
// Ini disebut "duck typing": kalau jalannya seperti bebek dan
// bersuara seperti bebek, JavaScript menganggapnya bebek.
Klik "Jalankan" untuk melihat hasilnya.

Latihan: Payroll Sederhana

Override hitungGaji() di Manajer (gaji pokok + tunjangan) dan Magang (setengah dari gaji pokok). Kode di bawah udah bisa menghitung total gaji dari array campuran, tanpa perlu tahu jenis karyawan yang mana — nah, itulah polymorphism lagi bekerja.

latihan-payroll.js — bisa diedit
Lengkapi kode lalu klik "Jalankan".
kunci-jawaban.js
class Manajer extends Karyawan {
  constructor(nama, gajiPokok, tunjangan) {
    super(nama, gajiPokok);
    this.tunjangan = tunjangan;
  }
  hitungGaji() {
    return this.gajiPokok + this.tunjangan;
  }
}

class Magang extends Karyawan {
  constructor(nama, uangSaku) {
    super(nama, uangSaku);
  }
  hitungGaji() {
    return this.gajiPokok * 0.5;
  }
}
5

Cek Pemahaman

1. Sebenarnya polymorphism itu apa sih?

Persis kayak aba-aba "mulai!" — satu perintah, respons beda-beda tergantung objeknya.

2. Di daftarBentuk.forEach(b => b.luas()), kenapa kode ini nggak perlu tahu apakah b itu Lingkaran atau PersegiPanjang?

Ini keuntungan utama polymorphism: kode pemanggil jadi lebih sederhana, nggak perlu banyak percabangan if/else per tipe.

3. "Duck typing" di JavaScript itu apaan sih?

Robot dan Manusia nggak berhubungan sama sekali, tapi keduanya bisa dipanggil bicara() secara seragam.

4. Di latihan Payroll, kenapa hitungGaji() perlu di-override di Manajer dan Magang?

Sama kayak bentuk: tiap jenis karyawan punya cara hitung gaji sendiri, jadi override diperlukan biar hasilnya benar.
Skor: 0 / 4 terjawab benar
6

Ringkasan Pertemuan 6

  • Polymorphism itu kemampuan objek-objek berbeda merespons method yang sama dengan cara masing-masing.
  • Kode pemanggil (misalnya forEach) nggak perlu tahu tipe spesifik tiap objek — cukup percaya method yang tepat bakal jalan.
  • Duck typing di JavaScript bikin polymorphism bisa jalan bahkan tanpa hubungan inheritance formal, asal method-nya cocok.
  • Polymorphism ini alasan sebenarnya kenapa method overriding (Pertemuan 5) begitu berguna — bukan cuma soal ganti satu class, tapi nyederhanain kode yang pakai banyak class sekaligus.
