Objek Pertamamu

Mengapa kita membutuhkan OOP dan bagaimana JavaScript menggabungkan data serta perilaku ke dalam satu kesatuan yang disebut objek.

Durasi: 120 menit Prasyarat: variabel, function, array Bahasa: JavaScript (ES6+)
1

Gudang yang Berantakan

Bayangkan kamu baru pindah rumah. Di garasi ada obeng, paku, kaleng cat, dan meteran yang menumpuk di lantai. Setiap kali ingin bekerja, kamu harus mengingat semuanya sendiri: "Cat warna biru itu milik siapa? Masih tersisa berapa liter? Obeng mana yang masih bagus?" Tidak ada tempat khusus untuk mengumpulkan barang-barang tersebut.

Hal yang sama terjadi pada kode procedural ketika aplikasi mulai membesar: banyak variabel terpisah yang sebenarnya berkaitan dengan satu hal, tetapi ditulis di tempat yang berbeda. Lihat contoh di bawah ini, lalu bayangkan jika jumlahnya bukan dua buku, melainkan 50 buku.

Inilah yang disebut Object-Oriented Programming (OOP), atau Pemrograman Berorientasi Objek. Intinya sederhana: daripada menambahkan variabel baru setiap kali ada data baru, kita membuat satu objek baru, yaitu satu paket yang berisi data dan cara mengolahnya. Perhatikan perbedaannya: gaya procedural di atas membutuhkan 3 variabel + 1 fungsi untuk setiap buku. Dua buku saja membutuhkan 6 variabel + 2 fungsi yang hampir sama. Untuk 50 buku, jumlahnya menjadi 150 variabel + 50 fungsi. Jika ada bug kecil pada logika tampilkanInfo, kamu harus memperbaikinya di 50 tempat berbeda.

Setiap buku baru membutuhkan 3 variabel + 1 fungsi baru. Data yang seharusnya berkaitan justru tersebar di berbagai tempat.

sebelum.js
let judulBuku1 = "Laskar Pelangi";
let penulisBuku1 = "Andrea Hirata";
let tahunBuku1 = 2005;

let judulBuku2 = "Bumi Manusia";
let penulisBuku2 = "Pramoedya Ananta Toer";
let tahunBuku2 = 1980;

function tampilkanInfoBuku1() {
  console.log(judulBuku1 + " oleh " + penulisBuku1 + " (" + tahunBuku1 + ")");
}
function tampilkanInfoBuku2() {
  console.log(judulBuku2 + " oleh " + penulisBuku2 + " (" + tahunBuku2 + ")");
}

tampilkanInfoBuku1();
tampilkanInfoBuku2();
Klik "Jalankan" untuk melihat hasilnya di sini.

Data dan cara menampilkannya menjadi satu paket dalam satu objek. Menambahkan buku baru tidak membuat variabel baru yang tersebar.

sesudah.js
const buku1 = {
  judul: "Laskar Pelangi",
  penulis: "Andrea Hirata",
  tahun: 2005,
  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
};

const buku2 = {
  judul: "Bumi Manusia",
  penulis: "Pramoedya Ananta Toer",
  tahun: 1980,
  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
};

[buku1, buku2].forEach(b => b.tampilkanInfo());
Klik "Jalankan" untuk melihat hasilnya di sini.
Perhatikan: method tampilkanInfo() di atas masih harus ditulis ulang di setiap objek. Inilah masalah yang akan kita selesaikan pada Pertemuan 2 dengan class, yaitu cetak biru yang memungkinkan method tersebut ditulis sekali untuk semua objek sejenis.

Pola yang sama berlaku untuk berbagai jenis data, bukan hanya buku. Bandingkan versi procedural dan versi objek untuk data motor di bawah ini.

motor-procedural-vs-objek.js
// --- gaya procedural ---
let namaMotor1 = "Vario";
let ccMotor1 = 125;
function infoMotor1() {
  console.log(namaMotor1 + " - " + ccMotor1 + "cc");
}
infoMotor1();

// --- gaya objek ---
const motor1 = {
  nama: "Vario",
  cc: 125,
  info() {
    console.log(`${this.nama} - ${this.cc}cc`);
  }
};
motor1.info();
Klik "Jalankan" untuk melihat hasilnya di sini.
Hasilnya sama, tetapi versi objek lebih mudah ditelusuri. Untuk melihat seluruh data motor, kamu cukup melihat satu variabel motor1 tanpa perlu mengumpulkan beberapa variabel terpisah.

Empat Pilar OOP — Sekilas

OOP dibangun di atas empat gagasan besar. Pada pertemuan ini, kamu cukup mengenal nama dan analoginya terlebih dahulu. Setiap pilar akan dibahas lebih mendalam pada pertemuan berikutnya.

Pertemuan 3

Encapsulation

Kotak perkakas yang dikunci: orang lain tidak dapat mengubah isinya sembarangan dan harus melewati "pintu" yang sudah kamu siapkan.

Pertemuan 4–5

Inheritance

Resep turunan: resep "Kue Dasar" diwariskan kepada "Kue Coklat" dan "Kue Keju", sehingga tidak perlu ditulis ulang dari awal.

Pertemuan 6

Polymorphism

Aba-aba "mulai!" dalam balapan: mobil melaju, motor melaju, dan sepeda melaju. Aba-abanya sama, tetapi cara setiap kendaraan bergerak berbeda.

Pertemuan 7

Abstraction

Tombol daya pada remote TV: kamu cukup menekannya tanpa perlu mengetahui rangkaian elektronik di baliknya.

Kotak Berlabel: Objek di JavaScript

Bayangkan semua alat di garasi tadi dimasukkan ke dalam satu kotak berlabel "Kotak Perkakas". Daripada mengingat banyak nama variabel yang terpisah, kamu cukup mengingat satu nama: kotaknya. Di JavaScript, kotak ini disebut objek, sedangkan cara menulisnya menggunakan kurung kurawal { } disebut object literal.

Barang di dalam kotak, yaitu data, disebut properti. Hal yang dapat dilakukan kotak tersebut, yaitu fungsi, disebut method. Sementara itu, this adalah cara objek merujuk kepada dirinya sendiri, seperti label di dalam kotak yang bertuliskan "isi kotak ini" tanpa perlu menyebut nama kotaknya.

Properti tidak hanya dapat berisi angka atau teks. Properti juga dapat berisi boolean (benar/salah), array, atau objek lain. Method dapat berisi berbagai logika, tidak hanya console.log. Hal yang membuatnya menjadi bagian dari OOP bukan bentuk kurung kurawalnya, melainkan data dan cara mengolahnya berada dalam satu wadah yang sama.

anatomi-objek.js
const kotakPerkakas = {
  // ---- properti (data di dalam kotak) ----
  obeng: 2,
  cat: "biru",

  // ---- method (hal yang bisa dilakukan kotak) ----
  cekIsi() {
    // "this" = kotak ini sendiri
    console.log(`Ada ${this.obeng} obeng dan cat warna ${this.cat}`);
  }
};

kotakPerkakas.cekIsi();
Klik "Jalankan" untuk melihat hasilnya di sini.

Berikut contoh dari domain lain dengan konsep yang sama: properti menyimpan data, method merepresentasikan perilaku, dan this merujuk kepada objek itu sendiri.

anatomi-objek-2.js
const kucing = {
  nama: "Milo",
  suara: "Meong",
  bersuara() {
    console.log(`${this.nama} berbunyi: ${this.suara}!`);
  }
};

kucing.bersuara();
Klik "Jalankan" untuk melihat hasilnya di sini.

Cek Pemahaman

1. Coba lihat objek buku tadi — mana yang disebut method?

Inget ya: properti itu data (judul, tahun), method itu fungsi di dalam objek (tampilkanInfo).

2. Sebenarnya this di dalam method sebuah objek itu ngapain sih?

this itu cara objek nunjuk ke "dirinya sendiri" — kayak label "isi kotak ini" di dalam kotak perkakas.

3. Kenapa sih kode procedural (banyak variabel lepas) susah berkembang begitu aplikasinya makin gede?

Persis kayak garasi berantakan tadi — makin banyak barang, makin susah tahu barang mana punya siapa.

4. Nah, pasangan analogi mana yang paling pas?

Kotak = objek, isi kotak = properti (data), aksi kotak = method (fungsi). Gampang, kan?

5. Kalau ada 50 buku ditulis pakai gaya procedural (kayak contoh di Bagian 1), kira-kira butuh berapa banyak variabel + fungsi lepas?

3 variabel + 1 fungsi per buku, dikaliin 50 buku — dan kalau ada bug, harus dibenerin di puluhan tempat berbeda.

6. Lihat objek kucing ({ nama, suara, bersuara() {...} }) — pernyataan mana yang bener?

Pola ini selalu berulang: properti = data, method = perilaku, this = "diri objek ini sendiri" — berlaku buat buku, kucing, motor, atau objek apa pun.
Skor: 0 / 6 terjawab benar

Ringkasan Pertemuan 1

  • Kode procedural menyimpan data yang saling berhubungan sebagai variabel terpisah, sehingga mudah berantakan ketika aplikasi membesar (2 buku = 6 variabel + 2 fungsi, 50 buku = 150 variabel + 50 fungsi).
  • Objek menggabungkan data (properti) dan perilaku (method) menjadi satu paket, seperti barang-barang dalam satu kotak berlabel. Pola yang sama berlaku untuk buku, motor, kucing, film, atau objek lainnya.
  • this di dalam method merujuk kepada objek itu sendiri, baik objek tersebut berupa buku, motor, maupun kucing.
  • Properti dapat berisi berbagai jenis data (teks, angka, boolean, atau array). Suatu "objek" memiliki data dan perilaku yang berada dalam satu wadah yang sama.
  • Empat pilar OOP — encapsulation, inheritance, polymorphism, dan abstraction — baru diperkenalkan secara singkat pada pertemuan ini dan akan dibahas lebih mendalam pada pertemuan berikutnya.
Selanjutnya

Di Pertemuan 2, object literal ini akan kita ubah menjadi class — cetak biru yang dapat menghasilkan banyak objek sekaligus tanpa perlu menulis ulang method satu per satu.
