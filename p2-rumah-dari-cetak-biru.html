Rumah Dari Cetak Biru

Dari objek yang ditulis satu per satu, kita beralih ke class: satu cetak biru yang bisa menghasilkan banyak objek secara konsisten.

Durasi: 120 menit Prasyarat: object literal & this (Pertemuan 1) Bahasa: JavaScript (ES6+)
1

Masalah yang Kita Tinggalkan

Coba bayangkan ada developer perumahan yang ingin membangun 50 rumah dengan tipe yang sama. Jika setiap rumah dibangun dengan cara menulis ulang seluruh denah dari awal — tata letak kamar, posisi pintu, dan cara pintu dibuka — prosesnya bukan hanya melelahkan, tetapi juga rawan salah. Satu denah yang keliru bisa membuat satu rumah menjadi cacat.

Itu juga yang terjadi pada object literal di Pertemuan 1. Coba jalankan kode di bawah ini dan perhatikan: method tampilkanInfo() ditulis ulang dengan cara yang sama di tiga tempat.

Masalah ini bukan hanya soal tenaga dan waktu. Bayangkan suatu hari kamu perlu mengubah format tampilan, misalnya menambahkan genre buku pada output. Dengan object literal, kamu harus memperbarui semuanya satu per satu di tiap objek. Kemungkinan lupa satu tempat pun sangat besar, dan hasilnya bisa tidak konsisten. Inilah yang disebut duplikasi kode — musuh utama kode yang mudah dirawat.

tiga-buku-diulang.js
const buku1 = {
  judul: "Laskar Pelangi",
  penulis: "Andrea Hirata",
  tahun: 2005,
  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
};

const buku2 = {
  judul: "Bumi Manusia",
  penulis: "Pramoedya Ananta Toer",
  tahun: 1980,
  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
};

const buku3 = {
  judul: "Cantik Itu Luka",
  penulis: "Eka Kurniawan",
  tahun: 2002,
  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
};

[buku1, buku2, buku3].forEach(b => b.tampilkanInfo());
Klik "Jalankan" untuk melihat hasilnya.
Masalahnya nih: kalau ada bug kecil di tampilkanInfo() — misalnya lupa spasi — kamu harus benerinnya di tiga tempat sekaligus. Kalau ada 50 buku, ya berarti 50 tempat.
2

Solusinya: Satu Cetak Biru, Banyak Objek

Developer yang pinter nggak bakal gambar ulang denah tiap rumah. Dia bikin satu cetak biru (blueprint) aja, terus tiap rumah baru tinggal "dicetak" darinya — cuma alamat dan pemiliknya yang beda, denah sama mekanisme pintunya tetap sama persis.

Di JavaScript, cetak biru ini disebut class. Bagian yang ngisi data unik tiap rumah (alamat, pemilik) disebut constructor, dan proses "nyetak rumah baru dari cetak biru" dilakukan pakai kata kunci new.

Satu lagi nih, perhatiin: nama class di JavaScript ditulis diawali huruf besar (RumahTipe36, Buku) — ini bukan aturan wajib dari bahasanya, tapi konvensi yang udah disepakati hampir semua programmer JavaScript, biar sekali lihat kamu langsung tahu mana class dan mana variabel biasa.

Satu class, dua rumah beda — denah dan method-nya sama, cuma datanya aja yang beda.

anatomi-class.js
class RumahTipe36 {
  // constructor = proses mengisi data unik tiap rumah saat dicetak
  constructor(alamat, pemilik) {
    this.alamat = alamat;
    this.pemilik = pemilik;
  }

  // method ini cukup ditulis SEKALI, dipakai semua rumah
  bukaPintu() {
    console.log(`${this.pemilik} membuka pintu rumah di ${this.alamat}`);
  }
}

// "new" = mencetak rumah baru dari cetak biru RumahTipe36
const rumahA = new RumahTipe36("Jl. Mawar No. 1", "Budi");
const rumahB = new RumahTipe36("Jl. Melati No. 7", "Sari");

rumahA.bukaPintu();
rumahB.bukaPintu();
Klik "Jalankan" untuk melihat hasilnya.

Kode Bagian 1 di atas, dirapiin jadi class Buku. Coba bandingin panjangnya — terus itung berapa kali tampilkanInfo() ditulis.

class-buku.js
class Buku {
  constructor(judul, penulis, tahun) {
    this.judul = judul;
    this.penulis = penulis;
    this.tahun = tahun;
  }

  tampilkanInfo() {
    console.log(`${this.judul} oleh ${this.penulis} (${this.tahun})`);
  }
}

const buku1 = new Buku("Laskar Pelangi", "Andrea Hirata", 2005);
const buku2 = new Buku("Bumi Manusia", "Pramoedya Ananta Toer", 1980);
const buku3 = new Buku("Cantik Itu Luka", "Eka Kurniawan", 2002);

[buku1, buku2, buku3].forEach(b => b.tampilkanInfo());
Klik "Jalankan" untuk melihat hasilnya.
Coba perhatiin: hasilnya identik sama Bagian 1, tapi tampilkanInfo() sekarang cuma ada SEKALI. Nambah buku ke-4, ke-5, ke-50 nggak nambah baris method sama sekali — tinggal satu baris new Buku(...).

Pola cetak biru yang sama ini berlaku juga buat kendaraan. Simpen contoh ini di kepalamu ya — Pertemuan 4 nanti bakal ngembangin ini lebih jauh.

class-kendaraan.js
class Kendaraan {
  constructor(jenis, kecepatanMaks) {
    this.jenis = jenis;
    this.kecepatanMaks = kecepatanMaks;
  }

  info() {
    console.log(`${this.jenis} bisa melaju hingga ${this.kecepatanMaks} km/jam`);
  }
}

const motor = new Kendaraan("Motor", 120);
const mobil = new Kendaraan("Mobil", 180);

[motor, mobil].forEach(k => k.info());
Klik "Jalankan" untuk melihat hasilnya.
Satu class Kendaraan, dua instance dengan data beda (motor dan mobil), tapi method info()-nya sama persis. Ini pola yang bakal terus kamu pakai buat semua class ke depannya.
3

Tiga Istilah yang Perlu Melekat

Dari dua contoh di atas, tiga istilah ini bakal terus muncul sepanjang kelas OOP kita, jadi hafalin baik-baik ya:

  • class — cetak biru. Ditulis sekali aja, isinya nentuin properti apa yang bakal dimiliki tiap objek dan method (perilaku) apa yang bisa dilakukan.
  • constructor(...) — bagian class yang otomatis jalan tiap kali objek baru dibuat, tugasnya ngisi properti awal dari data yang kamu kirim.
  • instance — satu objek nyata hasil "cetakan" dari class, dibuat pakai new NamaClass(...). Satu class bisa punya banyak instance, masing-masing dengan datanya sendiri.

Satu hal penting yang sering bikin pemula bingung: class itu sendiri bukan objek yang langsung bisa dipakai — dia cuma cetak biru/rancangan doang. Nulis class Buku { ... } aja nggak menghasilkan buku apa pun, sama kayak gambar denah rumah nggak bikin rumahnya beneran berdiri. Objek baru bener-bener "ada" setelah kamu manggil new Buku(...). Tiap instance juga independen satu sama lain — ngubah buku1.tahun nggak bakal ngaruh ke buku2.tahun sama sekali, meski keduanya dicetak dari class yang sama.

Latihan: Cetak Biru Mahasiswa

Coba lengkapi class Mahasiswa di bawah: constructor-nya nerima nama, nim, dan jurusan; method perkenalan() nyetak kalimat perkenalan. Terus buat minimal 3 instance mahasiswa yang beda-beda dan panggil perkenalan() masing-masing.

latihan-mahasiswa.js — bisa diedit
Lengkapi kode lalu klik "Jalankan".
kunci-jawaban.js
class Mahasiswa {
  constructor(nama, nim, jurusan) {
    this.nama = nama;
    this.nim = nim;
    this.jurusan = jurusan;
  }

  perkenalan() {
    console.log(`Halo, saya ${this.nama}, NIM ${this.nim}, jurusan ${this.jurusan}`);
  }
}

const mhs1 = new Mahasiswa("Dewi", "2201001", "Teknik Informatika");
const mhs2 = new Mahasiswa("Rafi", "2201002", "Sistem Informasi");
const mhs3 = new Mahasiswa("Putri", "2201003", "Desain Komunikasi Visual");

[mhs1, mhs2, mhs3].forEach(m => m.perkenalan());

Latihan tambahan: lengkapi class Produk buat toko online — constructor-nya nerima nama, harga, dan stok; method infoProduk() nyetak ringkasannya. Buat minimal 3 instance produk yang beda-beda.

latihan-produk.js — bisa diedit
Lengkapi kode lalu klik "Jalankan".
kunci-jawaban.js
class Produk {
  constructor(nama, harga, stok) {
    this.nama = nama;
    this.harga = harga;
    this.stok = stok;
  }

  infoProduk() {
    console.log(`${this.nama} - Rp${this.harga} (stok: ${this.stok})`);
  }
}

const p1 = new Produk("Kaos Polos", 75000, 20);
const p2 = new Produk("Celana Jeans", 250000, 8);
const p3 = new Produk("Topi", 45000, 15);

[p1, p2, p3].forEach(p => p.infoProduk());

Cek Pemahaman

1. Hubungan class dan object yang paling pas itu yang mana ya?

Persis kayak developer rumah: satu cetak biru (class) bisa nyetak banyak rumah (object/instance).

2. Kode di dalam constructor() itu jalannya kapan sih?

new NamaClass(...) otomatis manggil constructor sekali buat ngisi data awal instance itu.

3. Untungnya apa sih mindahin tampilkanInfo() ke dalam class, dibanding nulis di tiap object literal?

Inilah alasan utama Pertemuan 2 ini ada: ngilangin duplikasi method yang kita liat di Pertemuan 1.

4. Kalau kamu manggil new Mahasiswa(...) tiga kali dengan data beda-beda, apa yang bakal kejadian?

Kayak tiga rumah dari satu cetak biru: alamat dan pemiliknya beda, tapi denah dan cara bukanya sama.

5. Kalau cuma nulis class Buku { ... } doang (tanpa manggil new), udah menghasilkan buku yang bisa dipakai belum?

Kayak denah rumah: gambarnya nggak bikin rumahnya beneran berdiri. Instance baru ada setelah "dicetak" pakai new.

6. Kalau mhs1.nama diubah, apa yang bakal kejadian sama mhs2.nama (dua instance dari class Mahasiswa yang sama)?

Instance itu kayak rumah-rumah dari cetak biru yang sama: ngecat satu rumah nggak ngubah warna rumah tetangganya.

Ringkasan Pertemuan 2

  • class itu cetak biru yang nentuin properti dan method sekali buat semua objek sejenis. Class sendiri belum bisa dipakai — dia baru jadi objek nyata setelah "dicetak".
  • constructor(...) jalan otomatis sekali tiap kali objek baru dibuat, biasanya buat ngisi properti awal dari data yang dikirim.
  • new NamaClass(...) "nyetak" instance baru — satu class bisa menghasilkan banyak instance, masing-masing dengan datanya sendiri dan saling independen.
  • Mindahin method ke dalam class ngilangin duplikasi kode yang kita liat di Pertemuan 1 — bug cukup dibenerin di satu tempat.
  • Pola class-constructor-new yang sama ini berlaku buat domain apa pun: buku, mahasiswa, produk, kendaraan.
Tapi masih ada celahnya nih: properti kayak buku1.tahun masih bisa diubah siapa aja dari luar — bahkan diisi angka yang nggak masuk akal kayak -500. Class ini belum ngelindungin data di dalamnya.
